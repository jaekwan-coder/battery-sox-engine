# ecm.py 설명 — 왜 이렇게 만들었는가

이 문서는 [`src/models/ecm.py`](../../src/models/ecm.py) 코드가
왜 이런 구조로 만들어졌는지 설명합니다. 이론 자체(회로가 왜 이렇게
생겼는지)는 [`W1_electrochemistry_ecm.md`](W1_electrochemistry_ecm.md)를
먼저 보세요. 이 문서는 "그 이론을 코드로 어떻게, 왜 이렇게 옮겼는지"만
다룹니다.

---

## 🟢 쉬운 버전 — 처음 보는 사람용

### 이 파일이 왜 존재하는가

이 프로젝트의 최종 목표는 "달리는 차 안에서 전압·전류만 보고 SOC를
알아내는 것"이다. 이걸 하는 방법(칼만필터)은 항상 이런 문장으로
동작한다.

> "SOC가 이 정도라고 추측하면, 전압이 이렇게 나와야 맞는데..."

**이 문장에서 "SOC를 넣으면 전압을 계산해주는 부분"이 반드시 있어야
한다.** 그 계산기가 `ecm.py`다. 즉 `ecm.py`는 SOC 추정 그 자체가
아니라, **SOC 추정이 쓸 "부품"**이다.

### 왜 파라미터(R0, R1, C1)를 뽑기 전에 이 코드부터 만들었나

두 가지 이유가 있다.

**이유 1 — 나중에 재사용할 부품이라서.**
칼만필터가 완성되면, 그 안에 이 계산기를 그대로 가져다 쓴다. 건물의
철근 골조를 먼저 세우고 나중에 벽지(진짜 R0, R1 숫자)를 바르는 것과
같다. 골조 없이는 벽지를 바를 곳이 없다.

**이유 2 — 파라미터를 뽑는 코드를 검증하는 도구로도 쓰기 위해서.**
HPPC 실험 데이터에서 R0, R1을 뽑는 코드(`hppc.py`, 아직 미작성)를
만들면, 그 코드가 맞게 작동하는지 확인해야 한다. 이때
1. `ecm.py`에 **내가 이미 아는 값**(예: R0=0.02)을 넣어서
2. 가짜 실험 데이터를 만들고
3. 그 가짜 데이터를 `hppc.py`에 넣어 R0를 다시 뽑아본 뒤
4. 원래 넣었던 값(0.02)과 같은지 비교한다

`ecm.py`가 없으면 이 "정답을 아는 연습 문제"를 만들 수 없다.

### 코드 안에 뭐가 들어있나 — 세 부분
부분 1. 지금 배터리의 "상태" (숫자 세 개: SOC, 빠른반응, 느린반응)
부분 2. 전류가 들어오면 그 세 숫자가 어떻게 바뀌는지 (변화 규칙)
부분 3. 그 세 숫자로 지금 전압이 얼마인지 계산하는 공식


이 세 부분을 매 순간 "부분1 보기 → 부분3으로 전압 계산 → 부분2로
숫자 갱신 → 반복"하는 게 `simulate`라는 함수다.

### 파일 안의 이름들이 뭘 뜻하는지 (간단히)

| 이름 | 무엇인지 |
|---|---|
| `ECMParameters` | R0, R1, C1 같은 숫자를 담아두는 봉투 |
| `ECM` | 배터리 모형이라는 "물건" 자체 |
| `output_voltage` | 위 부분 3 — 전압을 계산하는 공식 |
| `discretize_zoh` | 위 부분 2 — 숫자가 시간에 따라 어떻게 바뀌는지 정확하게 계산하는 방법 |
| `simulate` | 이 모든 걸 시간 순서대로 반복 실행하는 엔진 |
| `HysteresisModel` | 충전/방전 곡선이 다른 현상(히스테리시스)을 계산하는 별도 부품 |
| `make_hppc_pulse_current` | HPPC 실험처럼 "휴지-펄스-휴지" 모양의 가짜 전류를 만드는 도구 |

### 이 파일은 HPPC용인가 EIS용인가

**둘 다 아니고, 그 위의 공통 도구다.** HPPC는 이 회로에 전류
펄스를 넣어 관찰하는 방법, EIS는 사인파를 넣어 관찰하는 방법이다.
`ecm.py`는 그 "회로 자체"이고, HPPC·EIS는 이 회로를 서로 다른
방식으로 관찰하는 두 실험이다. (다만 지금 `ecm.py`와 W2 노트북의
임피던스 계산은 아직 코드로 서로 연결·교차검증되어 있지 않다 —
이 부분은 `04_limitations.md`에 기록해둘 항목이다.)

## 🔵 기술 버전

### 설계 목표

`ecm.py`는 `W1_electrochemistry_ecm.md` M1.6에서 유도한 2RC+히스테리시스
등가회로를, 이후 두 용도에 재사용 가능한 형태로 구현한다.

1. **W3 파라미터 식별의 검증 도구**: 알려진 파라미터로 합성 HPPC
   데이터를 생성해, `identification/hppc.py`의 피팅 정확도를 검증
2. **W4-5 칼만필터의 예측 모델**: EKF의 상태전이함수·출력함수로
   그대로 사용될 예정 (`f(x,u)`, `h(x,u)`에 해당)

### 아키텍처

ECMParameters (dataclass)
└─ R0, R1, C1, R2, C2, Q_Ah 저장, tau1/tau2 프로퍼티 제공

ECM (class)
├─ continuous_A() / continuous_B() # 연속시간 상태공간 (W0 Q3)
├─ discretize_zoh(dt) # ZOH 이산화 (W0 Q8, D-002)
├─ output_voltage(state, I, h) # 출력방정식 (W1.6)
└─ simulate(time, current, soc0) # 이산 시뮬레이션 루프

HysteresisModel (class)
└─ dhdt(h, I, Q) # 1차 지연 히스테리시스 (W1.4)

make_hppc_pulse_current() # 합성 HPPC 전류 생성 (M3.1)
default_ocv_curve() / default_ocv_slope() # 합성 OCV + 해석적 야코비안

### 주요 설계 결정 (관련: `01_decisions.md` D-001, D-002)

**상태벡터를 `[SOC, V_RC1, V_RC2]`로 고정한 이유**: D-001에서 2RC를
채택했으므로, 상태 차원이 3으로 고정된다. 히스테리시스(`h`)는 상태벡터에
포함시키지 않고 별도 스칼라로 분리했다 — 현재는 전류 방향에만 의존하는
1차 지연으로 근사하고 있어, 엄밀한 상태공간 결합(공분산 상호작용까지
고려하는 W4-5의 EKF 상태)과는 아직 연결되어 있지 않다. 이는 알려진
한계이며, W4-5 구현 시 `h`를 정식 4번째 상태로 승격할지 결정 필요.

**ZOH 이산화를 SOC 성분과 RC 성분으로 나눠 처리한 이유**: `continuous_A()`의
(1,1) 성분이 0이라(순수 적분기) `A`가 특이행렬이 되어 표준 ZOH 공식
$B_d=A^{-1}(A_d-I)B$을 그대로 못 쓴다. SOC 행은 해석적으로 직접
적분(현재 직사각형 근사, 사다리꼴로 교체 가능)하고, RC 성분만 표준
1차 시스템 ZOH 공식을 적용했다.

**OCV 함수를 인자로 주입 가능하게(`ocv_fn`) 설계한 이유**: M3.2에서
실측 룩업테이블(보간 함수)이 나오면, `ECM` 클래스 코드를 건드리지
않고 `ocv_fn` 인자만 교체하면 되도록 하기 위함. 현재 `default_ocv_curve()`는
NMC 전형적 형태를 합성한 임시값이며, 실측값으로 교체가 예정된
플레이스홀더다.

### 알려진 미해결 연결 (한계)

- `ecm.py`(시간영역 시뮬레이션)와 W2 노트북의 `z_rc_parallel`(주파수영역
  임피던스 계산)은 현재 **독립적으로 구현**되어 있다. 같은 R0, R1, C1
  값을 넣었을 때 두 코드가 일관된 결과(M3.5 교차검증)를 내는지는
  아직 코드로 확인되지 않았다. 다음 작업 후보.
- `HysteresisModel`의 부호 규약은 `tests/test_ecm.py`에서 수렴 방향만
  검증했고, 실측 히스테리시스 크기(W1.4의 소재별 표)와의 정량 비교는
  아직 없다.

### 검증 상태

`tests/test_ecm.py`의 6개 테스트로 다음을 확인함(전부 통과):
R0 즉시강하, RC 계단응답의 해석해 일치(오차 4×10⁻¹⁶), 63.2% 규칙,
쿨롱카운팅 정확성, HPPC 펄스 구조, 히스테리시스 수렴. 상세 결과는
`docs/00_learning_log.md` "구현 과제 A, B" 항목 참고.
