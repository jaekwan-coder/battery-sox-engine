# 처음 오신 분께 — 읽는 순서 안내

이 저장소는 **리튬이온 배터리의 SOC/SOH/SOP를 추정하는 알고리즘**을
이론부터 구현까지 따라가는 학습 기록입니다. 전기·전자공학 학부 수준의
배경이 있고 세부 내용은 잊은 상태를 출발점으로 잡았습니다.

## 이 프로젝트가 답하려는 하나의 질문

> **배터리에는 잔량 센서가 없다.**
> 측정할 수 있는 건 단자전압·전류·온도 세 개뿐인데,
> 알고 싶은 건 셀 내부의 리튬 분포다.
> 이 간극을 어떻게 메우는가?

## 표기 규칙

- **W**n = Week, 주차 단위 (W0, W1, ..., W8)
- **M**n.m = Module, 해당 주차 안의 세부 모듈
  (첫 숫자가 주차 번호와 대응: W3 주차 → M3.1, M3.2, ...)
- **D**-nnn = Decision, 설계 결정 번호 (`01_decisions.md`)
- W0만 예외적으로 Q(Question) 번호를 씀 (자가진단 형식이라서)

## 전체 흐름 한눈에

```
[W0] 기초 도구 정비
      ↓
[W1] 셀 안에서 무슨 일이 일어나는가 → 회로로 번역
      ↓
[W2] 같은 회로를 주파수 영역에서 재확인 (EIS)
      ↓
[W3] 실험 데이터로 회로의 숫자 채우기  ← 수학 모델 완성
      ↓
[W4-5] 그 모델로 실시간 SOC 추정 (칼만필터) + 검증
      ↓
[W6] 노화를 추적 (SOH)
      ↓
[W7] 출력 한계 계산 (SOP)
      ↓
[W8] 실제 제품이 되려면 (임베디드, 기능안전, 규제)
```

## 반복되는 세 가지 주제

세부를 잊어도 이 셋을 잡고 있으면 재구성할 수 있습니다.

1. **정보의 문제** — 가관측성(W0 Q4), PE 조건(W0 Q7, W3 M3.4),
   LFP 평탄 구간(W1 M1.3)은 전부 "지금 들어오는 데이터에 알고 싶은
   것에 대한 정보가 담겨 있는가"를 묻습니다. 알고리즘 실패의 대부분은
   알고리즘이 아니라 **정보 부족** 때문입니다.

2. **시간 스케일** — ms(스위칭) / 초(RC 동특성, SOP) / 분(확산) /
   시간(SOC 변화) / 일~년(노화). 각 스케일마다 다른 도구를 씁니다.
   Dual EKF(W6)의 발상, RC 개수 선택(W1 M1.6)이 여기서 나옵니다.

3. **정확도 vs 검증가능성** — 파티클 필터가 양산에 없는 이유,
   딥러닝이 안전 루프 밖에 있는 이유가 같습니다. 이 업계에서는
   "잘 맞추는 것"만큼 **"어떻게 틀리는지 알고 증명할 수 있는 것"**이
   중요합니다(W8).
